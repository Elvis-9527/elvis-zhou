# 大量重复工作如何标准化

最近统计过一个月的工作日志。发现自己每天在做 8-12 件重复的事：
- 整理某格式的数据
- 根据模板改写某类邮件
- 拉取数据、生成报告
- 格式化某个表格
- 翻译或改写某段话

这些事加起来，占了工作时间的 40-50%。

我开始把这些重复的工作**写成"技能"（skills）**，用提示词来自动化。最后写了 91 个。

现在这不仅提升了效率，**更重要的是，我可以把这些技能交给别人，或者用来培训新人**。

## 什么是"技能"

在 Claude Code 里，一个"技能"（skill）是一组可重复调用的任务指令，也可以包含脚本、模板和参考资料。它对应一个**特定的、有明确边界的工作单元**。

不是所有的 AI 使用都应该写成技能。技能的关键特征是：

1. **高频重复**：每周至少做一次，最好每周多次
2. **低决策成本**：流程固定，不需要每次重新思考
3. **清晰的输入输出**：「我给你 X 格式的数据，你给我 Y 格式的结果」
4. **可交接**：别人读了 prompt，不用问你，也能用

### 不宜把整个任务直接标准化的情况

- 「帮我思考一个战略问题」：每次决策逻辑都不同，不能标准化
- 「帮我写一篇长文章」：虽然重复，但每篇都需要大量定制，交接成本高
- 「帮我分析一个案例」：分析框架多，单次调用成本不高，不必技能化

复杂任务也可以沉淀检查清单或研究框架，但不应把每次需要重新判断的结论固定下来。

## 我的 91 个技能从哪来

按工作领域分：

### 1. 数据处理（26 个）
- 格式转换（JSON → Excel、CSV → Markdown、HTML → 文本等）
- 数据清洗（去重、排序、填补空值）
- 数据聚合（多个表合并、字段映射）
- 数据分析报告（按模板生成基础统计、趋势）

例如，我有一个 skill 叫「导出钉钉群消息到 Excel」：
```
输入：钉钉群的消息导出文本（群名、消息人、时间、内容）
输出：规范的 Excel 表格，含 [日期] [发言人] [部门] [消息内容] [关键词]
规则：
- 如果发言人没有部门，从钉钉名单里查询并填补
- 关键词：按预定的 20 个词表来标记（如"改进""问题""建议"）
- 时间格式统一为 YYYY-MM-DD HH:MM
```

这个 skill 让我从手工整理 30 分钟的工作变成 2 分钟。

### 2. 文本处理（28 个）
- 邮件写作（按模板改写、针对不同收件人定制语气）
- 面试评价（候选人信息 → 标准的面试评价单）
- 会议记录（语音/文本 → 结构化的会议纪要）
- 反馈改写（生硬的反馈 → 建设性表述）

例如「候选人评价生成」：
```
输入：候选人简历 / 职位要求 / 面试官笔记
输出：标准评价单，含 [学历评价] [经验评价] [技能匹配] [文化适配] [综合建议]
规则：
- 每项评价必须有具体例子支撑（来自笔记）
- 建议项区分支持证据、风险和待核实事项；证据不足时明确标注，不强行下录用结论
- 语气中立、专业，不能有个人主观词汇
```

这让评价从"凭印象记"变成"可审计"。

### 3. 信息提取（18 个）
- 从长文本提取关键信息
- 从多个来源汇总信息
- 标签化和分类
- 结构化采访/访谈记录

例如「海外公司信息汇总」：
```
输入：公司官网、LinkedIn、新闻、财报摘要等多个来源的文本
输出：标准信息卡，含 [公司名] [成立年份] [融资阶段] [员工数] [主营业务] [最近融资] [估值] [创始人背景]
规则：
- 信息必须有来源注明
- 如果来源有矛盾（比如官网说 500 人，LinkedIn 说 800 人），两个都列出来并标注时间
- 没有找到的字段标记为"未找到"，不能猜测或补充
```

### 4. 工作流自动化（19 个）
- 定期报告生成
- 任务分配和提醒
- 工作日志整理
- 进度统计

例如「周报自动生成」：
```
输入：这周的日志记录（包括完成的任务、发现的问题、遇到的阻力）
输出：周报模板，含 [本周完成] [本周发现] [下周计划] [需要支持]
规则：
- 完成项要量化（完成了 N 个 task，推进了 M 个项目）
- 发现和问题要指向具体的行动（不是"效率低"，而是"X 流程导致文件在 Y 阶段停留了 Z 天"）
- 下周计划要可衡量（不是"继续推进"，而是"完成 XX 的可行性评估"）
```

## 为什么这么做

### 1. 效率是表象

我写这 91 个技能，节省的时间大概是**每周 8-10 小时**。这看起来是主要收益。

但更大的收益其实在别的地方。

### 2. 真正的收益：可交接性

一旦技能写清楚了，**我可以把工作交给别人**。

例如，我有一个新的 HR 助手。我不用花 2 小时教"怎么整理候选人信息"，而是：
- 给他看「候选人信息结构化」这个 skill 的 prompt
- 他读完就能用
- 他生成的结果是标准化的，我也不用花时间审查格式

这个 skill 成了**工作的"标准接口"**。

### 3. 可重现性和审计

当每个流程都写成技能以后，所有的工作都有了"配方"。

假如 3 个月前我生成了一份报告，现在需要重现同样的报告（更新数据），我可以：
- 调用相同的 skill
- 用新数据重新跑一遍
- 保持输出结构和检查规则一致，并复核内容

这对需要审计的工作特别有用（比如候选人评价、薪资推荐等）。

### 4. 知识积累

每个 skill 其实是一个**标准化的工作知识**。

我现在有 91 个 skill，相当于把我这半年最频繁的 91 个工作流程"冻结"成了代码。

新来的人想了解「我们是怎么做数据汇总的」「怎么写面试反馈的」，不用问我，直接看相应的 skill prompt 就行。

这是**把隐性知识变成显性知识**。

## 从 91 个技能里学到的规律

写到 50 个技能以后，我开始看到一些规律。

### 1. 工作其实是高度重复的

我花时间统计过：那 91 个技能，虽然看起来很多，其实对应的**核心操作只有 15-20 种**：
- 格式转换
- 文本标准化
- 信息提取
- 排序和分组
- 模板填充
- 对比和差异标记
- ...

剩下的 70 多个技能，都是这些基础操作的**组合和变种**。

这说明一个事实：**大部分的日常工作都是"配置型"的，不是"创意型"的**。

### 2. 技能的边界很重要

刚开始写技能时，我经常写得太宽泛。比如「数据处理」一个 skill，里面包括了数据清洗、格式转换、聚合、分析四个步骤。

结果是这个 skill 太复杂了，别人用的时候常常会不清楚"我应该用这个还是那个"。

后来我学会了**细分**：一个 skill 就做一件事。宽泛的工作流程，就写成多个 skill 的组合。

这样的好处是：
- 每个 skill 的 prompt 很清楚，不容易出错
- 可以灵活组合（一个 skill 可能被多个工作流程复用）
- 交接和维护都简单

### 3. 维护成本比想象的低

91 个技能听起来好像很多，但**维护成本其实不高**。

因为：
- 大多数 skill 一旦定型就不怎么改
- 改的通常只是参数（比如"标签词表从 20 个变成 25 个"）
- 有了版本管理以后，旧的 skill 也能保留

目前我花在"维护已有 skill"上的时间大概是**每月 2-3 小时**。

## 实践建议

### 1. 从最高频的工作开始

不要从头开始枚举。先看过去两周的工作日志，找出：
- 做过至少 2 次的工作
- 每次花超过 15 分钟的工作
- 重复的决策或判断逻辑

这些是最适合技能化的候选。

### 2. 先写 3-5 个，看效果

不要一口气写 91 个。先写最高频的 3-5 个，用一两周体验效果。

如果确实节省了时间，再继续。如果没有，也能快速调整方向。

### 3. 把 prompt 写得像"SOP"

好的 skill prompt，读起来应该像一份作业指导书，而不是随意的对话。

结构应该是：
```
[目的]：这个 skill 用来做什么
[输入]：需要哪些信息
[输出]：输出什么，什么格式
[规则]：遵循哪些规范（不能做什么、必须做什么）
[例子]：一个完整的例子
```

### 4. 文档化和版本管理

把所有 skill 的信息表编制出来：
```
| 技能名 | 频率 | 用途 | 版本 | 最后更新 | 谁在用 |
| --- | --- | --- | --- | --- | --- |
| 候选人评价生成 | 日均 2-3 次 | 面试评价 | v2.1 | 2026-11-01 | 我、HR 助手 |
```

这样别人能快速找到相关的技能，也能知道这个技能的成熟度。

## 最后的思考

当我写第 91 个技能时，我意识到一个更大的问题：

**日常知识工作中的一些重复环节已经可以交给 AI 辅助处理。但能否稳定复用，还取决于输入质量、判断边界和复核机制。首先要想清楚的是：这个工作的标准流程是什么。**

正是因为没有想清楚标准流程，所以我们每次都在"自己想办法"，导致了反复、低效、容易出错。

写 91 个技能，本质上是在**强制自己把日常工作的隐性规则显性化**。

一旦显性化了，不仅 AI 能用，别人也能用，新人也能学。工作效率自然就上来了。

而且，**一旦这套规则固定下来，你就可以从这些重复的工作里解放出来，把时间用在真正需要决策和创意的地方**。

这才是技能的真正价值。
